# 문서화 규칙 (Documentation Rules)

> CLAUDE.md 본문의 **작업 완료 체크리스트 / 세션 종료 절차 / 사용자 의사결정 변경 시** 3개 핵심 규칙을 보완하는 상세 지침.
> 핵심 규칙은 CLAUDE.md 본문에서 항상 로드되며, 이 파일은 디테일이 필요할 때만 참조.

## 갱신 트리거 (언제)

1. **PROJECT.md 갱신:** 로직에 중요한 변화 — 매매 전략, API 호출 패턴, Phase 전환, 아키텍처 변경 동반 시.
2. **TODO.md 갱신:**
   - 작업 완료 즉시 `[ ]` → `[x]` + 완료일.
   - 새 버그·기능 발견 시 **구현 시작 전에** Backlog 에 먼저 추가 ("기록 후 실행" 원칙).
   - "진행 중" 섹션은 다음 진입 후보 1~3개 명시.
3. **WORKFLOW.md 갱신:**
   - 작업 완료 즉시 완료 테이블 + 변경 이력 + 다음 작업 목록에서 제거.
   - 미완성 채로 세션 종료 시 "현재 작업" 섹션에 진행도/다음 명령어/블로커 기재 (CLAUDE.md "세션 종료 절차" 참조).
   - 사용자 의사결정 변경 시 Quick Status + "현재 작업" 섹션 즉시 갱신 (CLAUDE.md "사용자 의사결정 변경 시" 참조).

## "현재 작업" 섹션 템플릿 (세션 종료 직전 채우기)

```markdown
| 항목 | 값 |
|------|----|
| **작업 ID** | 예: R1 |
| **제목** | 예: /status 누적 손익 표시 |
| **진행도** | 예: 60% — persistence.get_total_pnl() 헬퍼 구현 완료, 회귀 테스트 작성 중 |
| **수정 중인 파일** | 예: persistence.py, notifier.py, test.py |
| **다음 실행 명령어** | 예: `python test.py` 후 test_get_total_pnl 실패 원인 디버깅 |
| **블로커/메모** | 예: SUM(pnl) 가 BUY 행 음수 pnl 포함하면 왜곡 — N15 우선 처리 검토 |
```

## 의사결정 변경 갱신 패턴 (예시)

오늘(2026-04-28) "관찰 모드 합의" 같은 변경 시:
- Quick Status `현재 Phase` 줄: "Phase 7 운영 — 관찰 모드(2026-04-28~). ... 사용자 합의 흐름: 손 떼고 페이퍼 데이터 누적 → Day ~7 R1 → Day ~14 B3"
- "현재 작업" 섹션: 관찰 모드 명시 + 다음 진입 시점·조건 + 새 세션 첫 액션 후보

→ 새 세션 Claude 가 옛 우선순위(예: N15 우선)를 따라가는 사태 방지.
